# Сравнение браузеров и матрица совместимости

Задача выбора: (1) в каких браузерах клиент проекта обязан работать — целевые браузеры;
(2) какой браузер удобнее для отладки и ревью клиентской части «Библиотеки КАИТ» — по нему считается взвешенная оценка.

Рабочее место: MacBook (Apple Silicon, arm64), macOS 26.6, 16 ГБ памяти. Проект запущен локально (PHP 8.4, MySQL 8.4).

## 1. Браузеры

| Браузер | Версия | Движок (рендеринг / JS) | Лицензия |
|---|---|---|---|
| Google Chrome | 157.0.8103.79 | Blink / V8 | проприетарная, бесплатно (основа — открытый Chromium, BSD) |
| Mozilla Firefox | 158.0 | Gecko / SpiderMonkey | MPL 2.0, свободная, бесплатно |
| Apple Safari | 26.6 | WebKit / JavaScriptCore | проприетарная, бесплатно (движок WebKit — открытый, LGPL/BSD); только macOS и iOS |

Три браузера — три разных движка. Яндекс Браузер, Edge, Opera построены на том же Blink, что и Chrome,
поэтому вместо второго браузера на Blink взят Safari: на iOS все браузеры работают на WebKit, а у студентов колледжа много iPhone.

## 2. Бенчмарки и память

Условия замера: MacBook Apple Silicon, macOS 26.6, 16 ГБ, питание от сети. Chrome и Firefox — отдельный экземпляр
с чистым временным профилем, одно окно, одна вкладка, без расширений (личные профили не затрагивались); Safari — единственное
окно с одной вкладкой. Другие программы (почта, мессенджер) оставались открыты, но не нагружали систему.
Бенчмарки запускались по очереди, никогда одновременно. Память — сумма `phys_footprint` (как «Память» в Мониторинге системы)
всех процессов экземпляра через 60 с после открытия 5 одинаковых вкладок (3 замера, каждый раз новый экземпляр): каталог, книга 1, ru.wikipedia.org/wiki/Браузер,
MDN Set-Cookie, php.net fputcsv. Холодный запуск — от команды запуска до появления окна, новый экземпляр с чистым профилем, 3 замера.

| Браузер | Speedometer 3.1 | JetStream 3 | MotionMark 1.3.1 | Память: 5 одинаковых вкладок, МБ (3 замера → среднее) | Холодный запуск, с (3 замера → среднее) |
|---|---|---|---|---|---|
| Chrome 157 | **60,0** ± 6,2 | **467,22** | **10 887,11** @ 60 fps | 563 / 431 / 416 → 470 (11 процессов) | 0,81 / 0,46 / 0,45 → **0,57** |
| Firefox 158 | 53,3 ± 5,3 | 294,11 | 2716,20 @ 60 fps | 1244 / 1072 / 1122 → 1146 (15 процессов) | 0,87 / 0,79 / 0,81 → 0,82 |
| Safari 26.6 | 57,4 ± 5,8 | не выполнен | не выполнен | 482 / 468 / 392 → **447** (10–12 процессов) | 0,54 / 0,54 / 0,71 → 0,60 |

В Safari нельзя было включить «JavaScript из Apple Events» (настройка безопасности), поэтому тесты запускались параметром
`?startAutomatically`, а результат читался из текста страницы. Speedometer прошёл; JetStream в Safari сильно замедлялся,
когда окно Safari оказывалось не на переднем плане (Safari притормаживает невидимые вкладки), результат признан
недостоверным и в таблицу не внесён; MotionMark без нажатия кнопки не запускается. Скриншоты — `benchmarks.png`.

## 4. Сеть: время ответа сервера (базовая линия для М10)

Network → строка запроса → Timing → «Waiting for server response» (TTFB). Измерялось через Navigation/Resource Timing
(`responseStart − requestStart` — то же значение, что показывает DevTools), 3 обновления, среднее. Сервер — встроенный
сервер PHP 8.4 и MySQL 8.4 на том же компьютере, поэтому значения маленькие. Firefox округляет таймеры до 1 мс.

| Запрос | Chrome 157 | Firefox 158 | Safari 26.6 |
|---|---|---|---|
| `index.php` (каталог) | 2,0 / 3,9 / 3,2 → **3,0 мс** | 3 / 3 / 3 → **3,0 мс** | не измерялось |
| `api.php?action=books.search` | 3,0 / 5,3 / 6,5 → **4,9 мс** | 4 / 5 / 4 → **4,3 мс** | не измерялось |
| `index.php?page=debtors` (под библиотекарем) | 4,6 / 7,4 / 4,7 → **5,6 мс** | 6 / 3 / 6 → **5,0 мс** | не измерялось |
| Всего запросов / объём страницы каталога | 6 / 17 КБ | 6 / 15 КБ | — |

TTFB в Chrome и Firefox практически одинаковый: он зависит от сервера и базы данных, а не от браузера.

## 6. Lighthouse по каталогу (базовая линия для М10)

Lighthouse 13.6.0, `http://localhost:8080/index.php?page=catalog`, чистый профиль Chrome без расширений (аналог окна инкогнито).

| Режим | Performance | Accessibility | Best Practices | SEO |
|---|---|---|---|---|
| Desktop | 100 | 83 | 100 | 82 |
| Mobile | 100 | 83 | 100 | 82 |

Метрики: Desktop — FCP 0,2 с, LCP 0,2 с, TBT 0 мс, CLS 0, Speed Index 0,3 с; Mobile — FCP 0,9 с, LCP 0,9 с, TBT 0 мс, CLS 0,
Speed Index 0,9 с. Отчёт: `lighthouse-before.html` (Desktop), скриншоты — `lighthouse.png`.

Три главных замечания Lighthouse:
1. **Недостаточный контраст текста** (Accessibility): серый текст класса `.muted` — «Найдено книг», автор и жанр в карточках.
2. **У выпадающих списков нет подписей** (Accessibility): `<select name="genre">` и `<select name="sort">` без `<label>` — экранный диктор не скажет, что это за поле.
3. **Нет meta description** (SEO): в `templates/layout.php` только `charset`, `viewport` и `title`.

Также: страница не попадает в back/forward cache — ответы приходят с `Cache-Control: no-store` (так PHP отдаёт страницы при открытой сессии).

**Браузер для отладки и ревью: Google Chrome.** Почему: единственный со встроенным Lighthouse (базовая линия для М10 снимается
в нём же), все пять нужных инструментов DevTools проверены на деле, лучшие результаты бенчмарков, проект работает без ошибок.

Проверка чувствительности: если поменять местами веса двух главных критериев К1 (0,30) и К3 (0,20) — Chrome 4,90,
Firefox 3,90, Safari 3,60, порядок не меняется. Chrome ни по одному критерию не хуже других, кроме лицензии (К7);
Firefox догнал бы его, только если вес лицензии стал бы больше суммы весов К2 и удвоенных весов К4 и К5
(сейчас 0,05 против 0,55). Выбор устойчив.

**Целевые браузеры проекта** — где клиент обязан работать:
- **Blink** — Chrome, Яндекс Браузер, Edge (две последние версии): самая большая доля пользователей в России, проверено в Chrome;
- **Gecko** — Firefox (последняя версия и ESR): другой движок, ошибки Chromium в нём не повторяются, проверено;
- **WebKit** — Safari на iPhone и Mac: у студентов колледжа много iPhone, а на iOS любой браузер работает на WebKit;
  проверено частично, полную проверку (особенно ширину 375 px на iPhone) нужно сделать в М13;
- ширина экрана от 375 px (телефоны) до 1920 px.
