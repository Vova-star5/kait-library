## 4. Конфликт форматирования

Файл: `src/ReportService.php`. Форматирование в VS Code (Shift+Alt+F) файл не изменило — он уже соответствует
стилю Intelephense (PSR-12), коммитить было нечего. `git diff --stat` после форматирования в NetBeans
(Source → Format, Alt+Shift+F): 19 строк изменено (8 добавлено, 11 удалено). Скриншот — `05_git_diff_format.png`.
Обратная проверка: тот же файл, отформатированный NetBeans, VS Code вернул почти к исходному виду (осталась 1 лишняя
пустая строка). Изменения NetBeans отменены `git restore src/ReportService.php`.

Чем отличаются форматтеры (отступы, переносы, пробелы, скобки): NetBeans ставит открывающую скобку класса и методов
на строку объявления (`class ReportService {`, `public static function debtors() {`), а VS Code по PSR-12 — на
отдельную строку; NetBeans добавляет пустую строку после `{` класса; продолжение аргументов при переносе
(`Database::fetchAll(` … и закрывающее `], ';');`) NetBeans сдвигает на 8 пробелов, VS Code — на 4.
Табуляции и окончания строк обе среды не трогали.

Чем это плохо для команды: если участники работают в разных средах, каждое сохранение файла в «чужой» среде
превращает в изменения десятки строк, где логика не менялась. В Pull Request такие правки закрывают собой
настоящие изменения, ревьюер их пропускает, а при слиянии веток возникают конфликты на пустом месте.
Решение — общие правила в репозитории и один форматтер для всех (модуль 4).
