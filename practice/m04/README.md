## 1. Что добавлено в корень проекта

Нормализация `.gitattributes`: `git add --renormalize .` не изменил ни одного файла в репозитории — все
текстовые файлы уже хранились с LF (последний файл с CRLF, `src/UserRepository.php`, исправлен в модуле 3).
Изменилась рабочая папка: до шага 49 файлов были `i/lf w/crlf` (git на этом компьютере с `core.autocrlf=true`
сам ставил CRLF при извлечении), после повторного извлечения — у всех текстовых файлов `i/lf w/lf`.

`launch.json` в `.vscode/` нет: проект не настраивали через `setup_kait`, отладка не нужна. Если он появится,
его не коммитим — в нём путь к PHP на конкретном компьютере.

## 2. Линтер

Линтер: PHP_CodeSniffer 4.0.4 (`phpcs.phar`, `phpcbf.phar` из `PP03/tools/php`).
Команда проверки: `C:\xampp\php\php.exe ..\PP03\tools\php\phpcs.phar --report=summary` (полный вывод — `lint-raw.md`)

| Замер | Ошибок | Файлов с ошибками |
|---|---|---|
| До автоисправления | 9 (предупреждений 0) | 4: `config/config.php` — 1, `public/api.php` — 3, `public/index.php` — 2, `src/helpers.php` — 3 |
| После автоисправления | 0 | 0 (`phpcbf` исправил все 9, коммит `517d306`) |
| Итог (после ручных исправлений / отключения правил) | 0 | 0 |

Отключённые правила и почему: дополнительно к `phpcs.xml` из заготовки — нет. В самом `phpcs.xml` отключены
`Generic.Files.LineLength` и `PSR1.Files.SideEffects` (в шаблонах HTML и PHP перемешаны),
`PSR1.Classes.ClassDeclaration.MissingNamespace` (в проекте нет пространств имён), а для `templates/*` —
проверки скобок, которые дают ложные ошибки на синтаксисе `if (...): ... endif;`.

Какие правила нарушались чаще всего: `Generic.ControlStructures.InlineControlStructure.NotAllowed` — 3
(`if (...) return ...;` без фигурных скобок в `plural()` из `helpers.php`), `PSR12.Files.FileHeader.SpacingAfterTagBlock` — 3
(нет пустой строки после `<?php`), `PSR12.Files.FileHeader.SpacingAfterDocblockBlock` — 2 (нет пустой строки
после заголовочного комментария файла), `Squiz.WhiteSpace.ControlStructureSpacing.SpacingAfterOpen` — 1
(пустая строка после `switch (...) {` в `api.php`).

Ошибок было мало, потому что в модуле 3 уже убраны табуляции и CRLF и разобран `LoanService::issue`.
После `phpcbf` (`git diff --stat`: 4 файла, +14 −4) приложение проверено контрольными сценариями модуля 3 —
все 8 ответов совпали с прежними (даты выдачи сдвинулись на 1 день, так как прогон на день позже), страница
должников с `plural()` выводит «606 дней», «604 дня».

## 3. Экспорт настроек IDE

| Среда | Как экспортировали | Файл в `practice/m04/` |
|---|---|---|
| VS Code | создан отдельный профиль «ПП03» (только настройки проекта и 4 расширения: Intelephense, EditorConfig, PHP Debug, русский язык) → «Профили» → «…» у профиля → «Экспорт…» → «Локальный файл» | `vscode.code-profile` |
| Apache NetBeans 31 | Tools → Options → Export → отмечены Editor, Formatting, PHP → zip; настройки форматирования проекта — в `nbproject/project.properties` (в репозитории), скриншот — `netbeans-formatting.png` | `netbeans-settings.zip` |

Профиль «ПП03» сделан не копией личного профиля: в личном профиле VS Code на этом компьютере лежат расширения
и настройки других проектов (в том числе данные для входа в сторонние сервисы) и форматтер Prettier с
табуляцией, который переписывает файлы при каждом сохранении. Такой файл нельзя отдавать в репозиторий. Экспорт проверен: в `vscode.code-profile` только
настройки редактора, список расширений и состояние окон — ни путей, ни ключей.

Экспорт NetBeans получился маленьким (4 файла): в него попадают только глобальные настройки, отличные от
стандартных. Стиль кода проекта NetBeans хранит не там, а в `nbproject/project.properties`, поэтому он
передаётся через `git clone`, а не через zip.

NetBeans `.editorconfig` не читает — правила пришлось продублировать в свойствах проекта. После этого
форматирование `src/ReportService.php` в NetBeans (Alt+Shift+F) меняет 1 строку вместо 19 в модуле 3:
закрывающую `], ';');` у массива внутри вызова функции NetBeans сдвигает на 4 пробела — отдельной настройки
для этого в NetBeans 31 нет. Поэтому в `CONTRIBUTING.md` записано, что решает линтер, а не форматтер IDE.

## 5. Сравнение способов передачи настроек

| Способ | Что передаёт | Плюсы | Минусы | Когда использовать |
|---|---|---|---|---|
| Файлы в репозитории (`.editorconfig`, `.gitattributes`, `.vscode/`, `phpcs.xml`, `nbproject/project.properties`) | правила, которые влияют на содержимое файлов: кодировка, LF, отступы, стиль кода, список нужных расширений | приходят всем вместе с `git clone`, меняются через PR, история изменений в git, не зависят от IDE (кроме `.vscode/` и `nbproject/`) | не передают личное (тема, клавиши); каждая IDE понимает свою часть: NetBeans не читает `.editorconfig`, пришлось дублировать | всегда, для всего, что должно быть одинаковым у всей команды |
| Экспорт профиля / настроек IDE в файл (`vscode.code-profile`, `netbeans-settings.zip`) | настройки самой IDE: параметры редактора, расширения, раскладку окон | можно передать готовую среду новичку одним файлом, работает без интернета | файл надо импортировать вручную и обновлять вручную; легко унести в файл личные данные (ключи, пути) — мы делали отдельный чистый профиль; привязан к одной IDE | разовая настройка нового рабочего места, учебный класс, одинаковые компьютеры |
| Синхронизация через аккаунт (Settings Sync) | все личные настройки пользователя между его компьютерами | автоматически, без файлов, сохраняет и тему, и клавиши | работает для одного человека, а не для команды; нужен аккаунт GitHub/Microsoft; синхронизирует и то, что к проекту не относится | свои настройки на своих компьютерах (дом и колледж) |

Вывод: для команды основной способ — файлы в репозитории: они приходят с `git clone`, проверяются в PR и
одинаково работают у всех, а линтер `phpcs` ставит последнюю точку независимо от IDE. Экспорт профиля
подходит как дополнение для быстрой настройки нового компьютера, Settings Sync — только для личных
настроек одного человека.
