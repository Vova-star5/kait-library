# Средства просмотра видео и стандарт видео-багрепорта

Задача выбора: (1) в каком формате команда записывает видео ошибок для Issues на GitHub;
(2) каким проигрывателем удобнее разбирать такие видео при ревью.

Ограничение площадки: GitHub на бесплатном тарифе принимает видео .mp4, .mov, .webm размером до 10 МБ.

## 1. Записанное видео

Что записано: находка модуля 3 — **студенту выдаётся шестая книга при лимите 5** (`src/LoanService.php:91`: условие
`$active['cnt'] > $limit` вместо `>=`). Сценарий 70 с: исходное состояние (каталог, вход библиотекарем, у студентки
Волковой 5 книг на руках) → выдача шестой книги INV-0009 — система выдаёт («Книга выдана до 03.12.2026») → после
обновления у Волковой 6 книг → седьмая книга INV-0011 уже не выдаётся («Превышен лимит книг на руках (5)»).

Программа записи: **OBS Studio 33.0.1** (macOS, Apple Silicon). Настройки: Вывод → Расширенный, запись в **MKV**,
кодировщик x264, управление битрейтом **CRF 20**, пресет veryfast, 30 кадров/с, базовое разрешение 1920×1080;
«Автоматически ремуксировать в MP4» — включено (OBS сам делает MP4 из MKV без перекодирования, как «Файл → Ремуксировать записи»).

Отличие от методички: источник — не «Захват окна», а **«Браузер»** (встроенный в OBS Chromium). Захват окна в macOS
требует разрешения «Запись экрана» для OBS; источник «Браузер» показывает проект без этого разрешения. Действия
пользователя (переходы, ввод email и инвентарного номера, нажатие «Выдать») выполняет страница-обёртка того же сайта:
она показывает адрес текущей страницы, указатель мыши, нажатия и подписи шагов. Микрофон и камера не использовались.

## 2. Форматы и настройки записи

Одно и то же видео в разных вариантах. MKV и MP4 — из OBS, WebM и MP4 720p — VLC 3.0.24 (Медиа → Конвертировать:
профиль «Video — VP80 + Vorbis (Webm)» и H.264 с масштабированием до 1280×720). Читаемость — один и тот же кадр
(0:24, таблица с email читателей) при 100 %, см. `variants-readability.png`. «Открывается в браузере» — файл открыт

## 4. Проверка по критериям

Задача выбора проигрывателя: каким проигрывателем ревьюер разбирает видео-багрепорт — находит кадр, где появилась
ошибка, замедляет, делает снимок кадра для Issue. Кандидаты: VLC 3.0.24, mpv 0.42.0, QuickTime Player 10.5
(встроенный проигрыватель macOS — вместо «Медиаплеера» Windows), Google Chrome 157 (видео перетаскивается в окно).
MPC-HC работает только в Windows и на рабочем месте (macOS) недоступен.

Веса и шкала записаны **до тестов** (отдельный коммит). Сумма весов — 1,00. Оценки 4 и 2 — промежуточные.

| Критерий | Вес | Почему такой вес | 5 | 3 | 1 |
|---|---|---|---|---|---|
| Открывает MP4, MKV, WebM | 0,15 | видео приходят в разных форматах | 3 из 3 | 2 из 3 | 1 из 3 |
| Покадровая перемотка вперёд / назад | 0,20 | главное при разборе — найти кадр, где появилась ошибка | вперёд и назад | только вперёд | нет |
| Замедление до 0,25× | 0,15 | быстрые действия видно только замедленно | 0,25× и медленнее | только до 0,5× | нет |
| Снимок кадра в файл | 0,15 | кадр с ошибкой прикладывается к Issue | одной клавишей или командой в файл | только в буфер обмена или через меню | нет |
| Повтор фрагмента A–B | 0,10 | многократный просмотр момента ошибки | есть | только повтор всего файла | нет |
| Увеличение части кадра | 0,05 | мелкий текст ошибки | масштаб и сдвиг части кадра | только полный экран или размер окна | нет |
| Нагрузка: CPU %, память МБ | 0,10 | разбор идёт параллельно с IDE и браузером | не хуже лучшего более чем на 30 % по обоим | хуже лучшего до 2 раз | хуже более чем в 2 раза |
| Лицензия, реклама, телеметрия | 0,10 | проигрыватель ставится каждому в команде | свободная, без рекламы и телеметрии | бесплатная проприетарная или есть телеметрия | реклама или платные функции |
| **Сумма** | **1,00** | | | | |

Результаты проверки. Как проверяли: функции mpv включались командами через его JSON IPC (`frame-step`,
`frame-back-step`, `speed`, `screenshot-to-file`, `ab-loop-a/b`, `video-zoom`), VLC — через RC-интерфейс (`frame`,
`rate`, `snapshot`, открытие трёх файлов), Chrome — через протокол отладки (открытие файлов). QuickTime управлять
скриптом не удалось: macOS не разрешает отправку ему команд без разрешения «Автоматизация», поэтому открытие форматов
проверено на деле (MP4 — открылся, MKV и WebM — окно «не удаётся открыть»), остальные функции — по меню программы
и руководству Apple. Нагрузка: одно и то же видео (MP4 1080p, вариант 2), 30 с воспроизведения, 3 замера; CPU — прирост
процессорного времени процессов проигрывателя и системного декодера VideoToolbox за 30 с (100 % = одно ядро),
память — `footprint` процессов проигрывателя; лист «Замеры» в `weighted-score.xlsx`.

| Критерий | Вес | VLC 3.0.24 | mpv 0.42.0 | QuickTime 10.5 | Chrome 157 |
|---|---|---|---|---|---|
| Открывает MP4, MKV, WebM | 0,15 | 3 из 3 → **5** | 3 из 3 → **5** | только MP4 → **1** | 3 из 3 → **5** |
| Покадровая перемотка вперёд / назад | 0,20 | только вперёд (клавиша E, команда `frame`) → **3** | вперёд и назад (`.` и `,`): 30,000 → 30,033 → 30,000 с → **5** | вперёд и назад (стрелки ← →) → **5** | нет → **1** |
| Замедление до 0,25× | 0,15 | `rate 0.25` принят (минимум 0,03×) → **5** | 0,25× и даже 0,1× → **5** | минимум 0,5× в меню «Скорость» → **3** | 0,25× в меню «Скорость воспроизведения» → **5** |
| Снимок кадра в файл | 0,15 | Shift+S / команда `snapshot` → PNG в папке → **5** | `s` / `screenshot-to-file` → PNG → **5** | только «Правка → Скопировать» в буфер → **3** | «Сохранить кадр видео как…» в контекстном меню → **3** |
| Повтор фрагмента A–B | 0,10 | кнопка «A→B» (Вид → Расширенное управление) → **5** | `l` / `ab-loop-a`, `ab-loop-b` = 28,0 и 34,0 с → **5** | только повтор всего файла → **3** | нет → **1** |

| Нагрузка: CPU %, память МБ | 0,10 | 18,7 % / 222 МБ → **5** | 25,9 % / 610 МБ (память в 2,7 раза больше лучшей) → **1** | не измерена (см. выше) → **3** | 15,1 % / 247 МБ → **5** |
| Лицензия, реклама, телеметрия | 0,10 | GPL, без рекламы → **5** | GPL/LGPL, без рекламы → **5** | бесплатная проприетарная → **3** | бесплатная проприетарная, статистика Google → **3** |
| **Взвешенная сумма** (из `weighted-score.xlsx`) | 1,00 | **4,60** | **4,60** | 3,10 | 3,20 |

Выбран проигрыватель для ревью: **mpv**. Почему: по взвешенной сумме mpv и VLC равны (4,60), и решает главный
критерий с наибольшим весом — покадровая перемотка (0,20): только mpv из свободных проигрывателей умеет шаг назад,
а найти кадр, где появилась ошибка, без шага назад неудобно. Кроме того, все нужные действия в mpv делаются одной
клавишей (`.` `,` `[` `]` `s` `l`). Минус mpv — память: 610 МБ против 222 у VLC (у mpv по умолчанию большой буфер
и программное декодирование).

Проверка чувствительности: mpv и VLC различаются только двумя критериями — перемоткой (5 против 3) и нагрузкой
(1 против 5), поэтому разница сумм mpv − VLC = 2 × вес перемотки − 4 × вес нагрузки; сейчас 2 × 0,20 − 4 × 0,10 = 0.
Если вес перемотки больше удвоенного веса нагрузки (например, перемотка 0,25 за счёт форматов 0,10) — mpv 4,60,
VLC 4,50, впереди mpv. Если меньше (например, поменять местами веса перемотки 0,20 и нагрузки 0,10) — VLC 4,80,
mpv 4,20, впереди VLC. QuickTime и Chrome лидеров не догоняют: у них нет повтора A–B и снимка кадра одной клавишей,
у QuickTime — ещё и MKV/WebM, у Chrome — покадровой перемотки. Вывод: **выбор зависит от того, что важнее — шаг назад
по кадрам (mpv) или экономия ресурсов (VLC)**; для разбора видео-багрепортов важнее первое, поэтому выбран mpv,
а VLC — запасной вариант для тех, кому нужен привычный интерфейс с меню.

## 5. Стандарт видео-багрепорта команды

Правила, по которым все участники записывают видео к Issues (используются с модуля 9):

- Формат, кодек, разрешение, частота кадров: **MP4, H.264**, 1280×720 (или окно браузера не больше 1280×720), **30 кадров/с**.
  MKV к Issue не прикладывать — GitHub его не принимает. WebM допустим, но VP8 портит цвета интерфейса.
- Настройки записи (программа, параметр качества): **OBS Studio**, Вывод → Расширенный → Запись: формат MKV, x264,
  **CRF 20**, пресет veryfast, выходное разрешение 1280×720; «Автоматически ремуксировать в MP4» включено (или
  «Файл → Ремуксировать записи»). Источник — «Захват окна» браузера с проектом (или «Браузер»), захват курсора включён.
- Длительность и размер: **30–90 с**, только воспроизведение ошибки (исходное состояние → действия → ошибка);
  **не больше 10 МБ** (лимит GitHub; при этих настройках 70 с ≈ 3,7 МБ).
- Что обязательно в кадре: **адресная строка** с полным адресом страницы, видимые нажатия и указатель мыши, исходное
  состояние (кто вошёл, какие данные), сообщение об ошибке или неверный результат на экране не меньше 3 с; если ошибка
  в JavaScript или сети — открытые DevTools (Console или Network).
- Что обязательно в тексте Issue рядом с видео: шаги воспроизведения, **ожидаемый и фактический результат**, время
  в видео, где видна ошибка (например, «0:27 — книга выдана»), браузер и версия, файл и строка, если известны;
  снимок кадра с ошибкой (`frame.png`) — отдельной картинкой.
- Чего не должно быть в кадре: настоящих паролей и личных данных (только тестовые учётные записи из `seed.sql`),
  уведомлений мессенджеров и почты (включить «Не беспокоить»), посторонних вкладок и закладок, микрофона и камеры.
- Где хранить, если видео больше лимита: сначала сжать (720p, CRF 23–26, обрезать лишнее); если всё равно больше
  10 МБ — загрузить в облако колледжа (или Mail Облако) с доступом по ссылке и дать ссылку в Issue, а в репозиторий
  видео-черновики не коммитить (`.gitignore`: `practice/m07/*.mkv`, `*.webm`, `draft*`).
